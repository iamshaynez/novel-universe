g01 存档自愈与续档门控（v1.1）验收证据
日期：2026-11-02 · 分支 fix/save-recovery

一、事故复盘（用户报告的三症状与根因）

1. 「本地存档出了岔子」后回到第一章开头 —— 旧存档 × 新内容图结合部：锚点要求
   ID+内容指纹双匹配，一句台词修订即降级到场首；断链推进直接报错死局。
2. 连接后端后直接进局、无法选档 —— tryResume 无条件自动续档（marker 的 at
   时间戳从未被读取），目录请求返回后立刻把玩家拽进上一档。
3. 局内点「存档」无反应 —— b8d32c8 给 openSaves 加 refresh 参数后按钮仍直挂
   `onclick = openSaves`，click 事件对象被误当 refresh，requestPanel 被跳过、
   settlePanel 因 pendingPanel 不符而空转，面板永远打不开。

二、设计（ADR-007 v1.1 修订）

- 锚点结构优先：ID 在且仍是停点 → 原位；内容指纹只标记「台词被改过」。
  指纹只看内容不看 id（场景重写换 id 也能找回）。ID 消失才走 场内→全作
  指纹找回 → 场首 → 章首 → 卷首。
- 断链自愈：读档时 canProceed 干跑校验（line 走链 / choice 全选项 /
  transcribe 正确项），推不动沿 原位→场首→章首→卷首 落到健康停点。
- 降级留底：位置被回拨前，原进度以确定性 id `{docId}-backup-{irHash}`
  备份成分支档（note=内容更新前的进度备份）随同步传播，进度永不单点。
- 迁移是版本化写入：bump vv + 置脏（旧策略「不递增」导致远端永远收不到
  对位、拉取时又被旧副本静默顶替）；samePayload 剥离 seq，服务端「同负载
  并发取大向量」路径自此才真正可达。
- 同步：干净档被并发顶替同样分叉保命（唯一例外：干净活档撞墓碑跟着删，
  删除语义不回滚）；applyRemote 与 LocalRuntime 共用每档 Web Lock，读改写
  不再互相插队。同负载的「真领先」静默落库，不弹跟进提示。
- 续档门控（resumePlan）：仅 PWA 独立窗口重开且标记新鲜（7 天）才自动
  直进；普通浏览器落封面，卡片显式标注「续读 · 第X章 · 存档 xxxx」。
- 致命错误逃生舱：本地档推不动 → 常驻错误条（#fatalBar，模态）+ 两条出路
  「重新对位本档」（读档即自愈链路）与「回到封面」；坏档记账
  brokenLastPlay（首拍走通即撤销），下次开卷不再自动续进——坏档 × 自动
  续档不成环。
- 存档按钮回归修复：`btnSaves.onclick = () => openSaves()`，openSaves 只认
  字面 true 的刷新态。

   症状消除；PWA 独立窗口的自动续进由 resumePlan 单元测试保障。

   session-resilience 接线合同约束。
