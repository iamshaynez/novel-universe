# 提案：宇宙持续迭代框架 v1

> 回答一个问题：这个框架能否支撑「一个统一宇宙 + N 部独立成篇的作品 + 永续迭代」？
> 结论：骨架成立，不需要重构；需要七个按序增量（§4）。本文档是后续迭代的锚点，
> 与《宇宙-成都-v0.md》（宇宙宪法）、《指南-悬疑小说拆解-v1.md》（单作流水线）配套。

## 1. 技术框架：四层不变式 + 一条治理链

| 层 | 内容 | 复杂度主张 |
|---|---|---|
| 引擎层 `engine/` | IR + 选择序列 → 状态，纯函数 | **不认识宇宙**。宇宙长多大这层不变；测试走 `test/fixtures/`，永不为内容改引擎 |
| 正典层 `universe/` | 双层时间轴、人物网、地点、令牌 | 宇宙的全部复杂度**只进数据**；增长=minor，改含义/删除=major（全量变红，影响面一目了然） |
| 作品层 `games/` | 剧本 DSL + 设计文档，一作一目录 | 作品复杂度**只进自己目录**；跨作共享只经正典引用；加一部新游戏 ≈ 新增一个目录 + 声明 assumes |
| 工具链 `tools/` | 编译 / lint / 图校验 / 可达性 / 脚手架 | 复杂度**不靠人记住，靠门挡住**：每次变更全宇宙重编译重验证，任何越界引用编译即失败 |

治理链（每轮变更的完成定义）：`写内容 → 编译通过 → canon-lint（纪元/版本/年代）→ 分支图（结局全可达）→ e2e（全分支回放）→ PR 三合一评审（正典 diff + 剧本 diff + 测试 diff）`。

**公理：新增的每一件事，要么是数据增量，要么被已有的门挡住。**

## 2. 文学框架：宇宙四轴 × 作品四选 × 三条交叉通道

**宇宙层（相对稳定，跨作品共享）**
- 空间轴：城市与锚点地点（府南河/东郊/玉林/茶馆…）
- 时间轴：双层事件轴（公共历史免费引用；私有秘密走纪元）
- 人物网：出道制 + 出生年 + 年代阶段（时间客串）
- 母题轴：跨作品押韵的主题（消失与留下 / 市井的善意连锁 / 体面）

**作品层（每作自由，单本必须好看）**
- 年代切片：`set_in` 一个（或一段）年代
- 容器：诡计类型 × 体裁 × 节奏（指南 P0 立项四要素：诡计类型/玩家定位/体量/死亡名单）
- 视角：玩家以什么身份进入（侦探/当事人/嫌疑人/多视角群像）
- 母题押韵：至少与一个宇宙母题押韵

**三条合法交叉通道**（伊坂式的三种链接，lint 可验证）
1. **公共历史**：`layer=public` 事件，任何作品免纪元引用。
2. **客演**：人物出道（`first_appearance`）后跨作登场；时间客串 = 同一人在不同年代切片里是不同的人生阶段。
3. **旧案回声**：「可提其事，不提其解」——晚年代作品可提及早年代事件，但其诡计归属在正作披露前保持 ⊘。

**文学公理：宇宙提供坐标（何时何地何人），作品提供容器（什么样的故事）；
宇宙押韵主题，作品独占真相。** 一部作品的 who/why 永远是该作的私有正典，
宇宙层永不持有「当前进行时的谜」。

## 3. 需求覆盖现状（诚实版）

| 需求 | 支撑机制 | 状态 |
|---|---|---|
| 统一背景/时间线/公共事件 | universe 单一事实源 + 双层 timeline + canon semver | ✅ 已建（人物年代化、set_in 除外） |
| 一致的人物设定 | 人物档案 + 出道制 + 纪元 lint + bio 双层 | ✅ 已建（年代阶段 schema 缺） |
| 多部独立作品、类型各异 | 一作一目录 + assumes 知识声明 + 指南 P0 诡计类型判定 | ✅ 机制在，待首作验证 |
| 与背景交叉（历史/时间轴/人物） | 三条交叉通道 | ✅ 通道在；客演的时间维度待 schema |
| 持续迭代不冲突 | 编译即加载 + semver 隔离破坏面 + PR 三合一 | ✅ 已建 |
| 可玩 | server API + 文字舞台播放器 | ✅ 已建（g00 即活样板，现居 fixtures） |
| 可测试 | 64 测试：引擎/编译/图/API/e2e 全分支回放 | ⚠️ **可达性有测试，公平性无测试**（§4.1） |

## 4. 缺口路线图（按优先级）

1. **释放矩阵数据化 + 公平性 lint**（最大缺口，悬疑类型的专属质量门）
   `design/matrix.md` → `design/matrix.json`（行=知识点，列=章，✓/◇/✗/⊘）；
   lint 规则：真结局所需知识点必须 ✓ 或主干保底 ◇；红鲱鱼必须有回收标注。
   e2e 证明「所有结局玩得到」，公平性 lint 证明「该给的线索都给了」。
2. **人物年代化 schema**：`birth_year` + `stages: [{era, 一句话人生阶段}]`。
   时间客串与「啊，他变成这样了」的前提。**首作开写前完成**（影响初始档案形态）。
3. **`set_in` + 年代穿越 lint**：game.json 声明故事年代；引用晚于该年代的
   公共事件 = 编译失败（年代穿帮与剧透同级）。**首作开写前完成**。
4. **地点×年代快照**：同一地点不同年代的 mood 配方与可用物件。
5. **build-wiki 设定集**：canon JSON → 人类可读 HTML，宇宙变大后的查询界面。
6. **母题层入 canon**：`universe/themes.json`，作品 manifest 声明押韵的母题。
7. **群像创作模式**（指南增补）：多视角=多章多视角人物的操作指引与 DSL 惯例。

顺序建议：1–3 在首部正传立项前完成（它们决定人物档案与 game.json 的初始形态）；
4–7 随作滚动补。全部是增量，不动引擎。

## 5. 一句话总结

引擎不知道宇宙有多大，宇宙不知道哪部作品最好看，工具链替双方站岗——
作者只负责一件事：把下一个故事写好看。
