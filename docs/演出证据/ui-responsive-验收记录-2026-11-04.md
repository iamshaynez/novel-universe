# 响应式 UI 与登录验收证据（2026-11-04）

分支：`fix/responsive-ui-auth`。验收使用本地隔离 SQLite 数据库；正式作品内容用于封面、登录、HUD、导读与选项，仓库既有 `g00-demo` 测试作品用于时间轴与结局卡。未修改测试作品或正式剧情。

## 实测结果

- **390×844 手机竖屏**：封面完整居中；作品卡与账号入口保持纸面配色；注册表单无裁切。实际键入中文用户名与含空格密码 `final pass 123`，密码框 Enter 成功注册，模态关闭后焦点落到可见的「退出」按钮。
- **320×568 窄屏**：登录/注册切换、输入框、错误区与按钮完整可见；Escape 关闭后焦点回到「注册/登录同步」。
- **844×390 手机横屏**：封面和登录卡可用，短屏纸卡内部滚动；结局卡三个操作均在可视区内。
- **768×1024 iPad 竖屏**：8 个 HUD 按钮同排，左右边界为 16px / 752px，无裁切；卷宗侧签不再探出屏幕。
- **1024×768 iPad 横屏**与**1440×900 桌面**：正文、选项、环境层与 HUD 分区正常；桌面选项完整可见。
- **导读与侧面板**：手机导读可打开、关闭并返回当前选项；面板边界、页签与关闭钮可见。
- **时间轴与结局**：时间轴位于 HUD 和正文之间；手机结局按钮自动换行，短横屏结局按钮同排且完整。

## 验收边界

本次为 ZCode 内置 Chromium 浏览器的真实渲染、鼠标/键盘操作与多视口检查，不是 iPhone/iPad 真机 Safari。已接入 `visualViewport`、动态 `dvh`、安全区和软键盘缩放规则，但真实 iOS 软键盘、粗指针媒体查询及主屏幕 PWA 仍需真机复核。运行环境不提供浏览器 console 监听，因此未收集控制台日志；所有已测页面均未出现可见错误。高层定位点击在该内置浏览器中出现超时，已用坐标化真实鼠标配合 `elementFromPoint` 命中检查交叉验证，未使用脚本点击绕过页面逻辑。
