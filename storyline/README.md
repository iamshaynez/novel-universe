# Storyline Backlog · 故事积压库

> 宇宙的剧本候选池。每个文件是一部通过独立评审的完整故事构想（终稿原文）。
> 这里只有**故事**，没有工程——工程在小说写完之后才进场。

## 生产管线（已定的总顺序）

```
storyline/ 选题 → 小说创作（完整小说文本，真相在此定稿）
→ 按 docs/指南-悬疑小说拆解-v1.md 拆解（真相正典化→线索系统→游戏结构）
→ games/gNN 剧本化 → 文字舞台
```

**小说先行**：先把完整小说写好，再构建游戏。理由：
1. 指南本身就是「小说 → 游戏」的拆解框架，小说是真相层的天然载体；
2. 小说的创作门槛低于 DSL 剧本，backlog 里可以有永远不成游戏的好故事——这是特性不是浪费；
3. 游戏化时公平性（释放矩阵）有小说全文可对照，拆解质量更硬。

**两条纪律（小说阶段就要守住）**：
- 公平性在小说里埋好——真结局所需的每个要素，小说正文必须让读者「应该已知」；
- 正典同步——小说定稿的真相（who/why）按指南 P1 正典化进 universe 私有层，披露作品随立项指派。

**待设计（启动首部详细剧本开发时）**：小说文本开发的工作流程与工程结构
（章节目录结构、正典同步的触发点、评审门、从小说到线索卡/释放矩阵的拆解工件）。
