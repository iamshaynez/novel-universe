g01 换版打断开局演出事故排查与加固（v0.5.3 候选）验收证据
日期：2026-11-02 · 分支 fix/update-plan-stop-points

一、用户报告

第一章「上岗」章节名出现时，点击「第一章」三个字附近直接闪回；
第一章入场动画可无限重复——点就闪回去，点就闪回去。

二、排查结论（当前构建复现不出卡重放本身）

- 编译产物干净：全部节点带 chapter，换章分支不会因章号缺失反复触发。
- 桌面输入路径干净：章节卡窗口内 15 连击，章节卡只出现 1 次、零 wipe、
  零重载，点击正常过印章 gate 与台词拍。
- 对用户存活标签页的法证：已续档于 ch1（6 行），veil 关、无面板、
  session 无换版记录；toast「回到上次的本地停点」表明经历过自动续读。

根因（复合环境事故，非单一代码缺陷）：
1. 当天三次部署（v0.5.0/0.5.1/0.5.2）+ 本地 3000 服务多次重启，bundle 换了三次；
2. 用户的长存活标签页持旧壳，版本哨兵每次发现 bundle 变化即 armForceUpdate；
3. 旧实现带 1200ms 急切 reload 定时器，不等停点——章节卡/开场演出演到一半
   被 location.reload() 打断（即「闪回」）；
4. 重载落地后若 lastPlay 指向已结局存档（共享 IndexedDB 的测试标签页跑出过
   结局），tryResume 清标记回封面——再点开局，第一章入场动画又重放。
   部署窗口内反复发生即用户所见。

三、加固（换版执行计划，策略提为纯函数）

web/resilience.mjs 新增 updatePlan({running, endcard, pageAgeMs})：
- defer：页面年龄 <15s 一律缓换（章节卡/开场演出/SW 落位窗口），稍后重评；
- wait-stop：局内置 forceUpdate，由 runLoop 在拍间隙（自然停点）换版，
  删除 1200ms 急切 reload——换版永不与揭示竞速；
- reload-now：封面无局或结局页（天然停点）直接换。
web/player.mjs armForceUpdate 按计划执行；防环指纹守卫移到缓换之后
（defer 不烧掉守卫，稍后仍可换）。

四、自动验证与冒烟

- test/session-resilience.test.mjs 新增 3 场景（先红后绿）：新鲜页面缓换、
  局内只认停点、封面/结局页直接换。
- 全量 npm test 266/266；npm run verify PASS（E1/E2/E3，2160 条路线）。
- 浏览器冒烟：新壳开局推进正常（10 行、无报错）。
