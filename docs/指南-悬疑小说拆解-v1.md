# 指南:悬疑小说 → 游戏的拆解框架 v1

> 输入:一篇悬疑小说的构思。输出:一部可验证、可发布、公平性有保证的悬疑文字游戏。
> 本文档是创作期的操作手册:未来 agent 与作者按阶段顺序执行,每个阶段有明确的
> 输入 / 动作 / 产出 / 完成门,不满足完成门不进入下一阶段。

## 0. 三条总原则

1. **真相是数据,披露是设计。** 小说靠"藏",游戏靠"受控地给"。先把真相全部摊开
   正典化(Phase 1),再设计玩家在何时以何种方式知道什么(Phase 2)。顺序颠倒必返工。
2. **公平性必须可验证。** 真相揭晓时刻,解题所需的每个要素都必须是玩家"应该已知"
   的——这条不靠自觉,靠释放矩阵 + 校验(Phase 6)。
3. **先图纸后施工。** 真相档案 → 线索卡 → 释放矩阵 → 分支图 → 剧本 → 演出标注。
   直接写剧本 = 把结构问题埋进散文里,后期无法检查。

## 1. 阶段总览

```
P0 立项审查 → P1 真相正典化 → P2 线索系统 → P3 游戏结构
→ P4 剧本写作 → P5 演出标注(与P4穿插) → P6 校验与试玩 → P7 发布归档
```

依赖关系:P2 需要 P1 的真相;P3 需要 P2 的矩阵(拓扑必须能保证"必须未知");
P4 需要 P3 的图;P6 检查 P2/P3/P4 三层是否互相兑现。

## Phase 0 · 立项审查(半天)

**输入**:小说构思(梗概、诡计、结局)。

**动作**
- **诡计类型判定**,决定改编难度与对策:
  - 信息差型(读者缺信息)→ 最适合,天然映射为线索释放;
  - 叙述诡计型(叙述者误导)→ 可用,但必须检查"玩家=主角"视角是否会提前泄底,
    必要时改玩家角色定位;
  - 逻辑型(信息全给、推理难)→ 最适合推理玩法(连线/指认)。
- **玩家角色定位**:侦探 / 当事人 / 嫌疑人之一 / 多视角。这决定信息不对称结构,
  是整个游戏叙事的地基,定了不改。
- **体量定标**(首作建议):3–5 章、2–3 结局、8–15 张线索卡、1–2 条红鲱鱼。
- **死亡名单**:不可改的核心(诡计核心、真凶、动机、关键逆转)。后续一切设计
  不得触碰这四项。
- `node tools/new-game.mjs gNN-slug 标题` 起目录,改 game.json 的 code/assumes/canon。

**产出**:`games/gNN/立项.md`(上述四项)+ game.json。

**完成门**:能用三句话讲清——真相是什么;玩家以什么身份、靠什么行为逼近它;
结局分几层。讲不清 = 回去改构思,不开工。

---

## Phase 1 · 真相正典化(1–2 天)

把小说家藏的东西**全部摊开**,写成《真相档案》。这一步只有先做完,后面的
"给玩家看什么"才有得设计。

**动作**
1. **真实时间轴**:案发前后每个事件,id / date / title / 真实 summary / depends_on。
   直接按 `universe/timeline.json` 的形态写。
2. **人物全档**:每人 bio_public(公开人设)+ bio_secret[](真实动机、案发夜的
   实际行为、知情范围;每条预留 revealed_in)。
3. **物证真值清单**:每件证物的客观事实与真实含义(与表面含义相对)。
4. **知情矩阵**:谁在何时知道什么——对峙戏的弹药库。
5. **拆正典**:
   - 跨作复用的(人物/地点/核心事件)→ `universe/` 增量(canon minor,独立 PR 评审);
   - 本作一次性案情细节 → `games/gNN/design/truth.md`(私有设计文档,不进正典,
     避免污染共享宇宙)。
6. **素材台账**(喂给演出层的数据,见附录 C):人物 → 主题色(iris)、声线
   (voice_hz)、分侧站位(左/右);地点 → 印章文案、氛围配方参数(时间/天气
   变体、rain/sign/bigchar 氛围开关);证物 → 演出形态(纸/雾字/纽扣/灯牌…)。

**产出**:timeline/characters 增量 + `design/truth.md` + 素材台账。

**完成门**:canon-lint 通过;真相档案里任何一桩"公开层矛盾"都能指到具体
secret 条目;正典 diff 单独成 PR(评审三合一,见 AGENTS)。

---

## Phase 2 · 线索系统设计(2–3 天,悬疑游戏的心脏)

从真相**反推**玩家侧的镜像。

**动作**
1. **解题链**:真相 = f(哪些最小知识)?画出链式推理图 `纽扣 → 茶寮 → 常客名单
   → 小桃在场 → …`。链必须闭合(无断环、无死枝)。
2. **线索卡**(每张固定字段,模板见附录 A):
   - id / 客观物 / **获得方式**(哪个场景 + 什么条件:选择、好感、调查);
   - **表面解读**(玩家第一眼以为的意思)/ **真实含义**(指向解题链哪一环);
   - **误导方向**(红鲱鱼专属:它想让你去哪、为什么合理、揭晓时如何回收);
   - **连线关系**(与哪些卡可组成推断 → 生成什么新知识);
   - **演出形态**(对应演出词汇表:证物卡 / 文档纸 / 红笔圈词 / 印章…)。
3. **释放矩阵**(核心工件,模板见附录 B):行 = 知识点(线索卡 + 推断),列 = 幕/章。
   每格四选一:
   - ✓ 必须已知(主线上必给)
   - ◇ 分支可知(某条线可得;要写清哪条)
   - ✗ 必须未知(**且写明由什么保证**:分支隔离 / flag 守卫 / 视角不在场)
   - ⊘ 永不公开(只存在于真相档案)
4. **公平性自查(第一次)**:真结局所需的全部知识点,是否都是 ✓ 或"主干保底的 ◇"?
   若某要素只在 30% 概率分支 → 要么挪进主线,要么结局判定降级。
5. **红鲱鱼回收方案**:每条误导在揭晓幕必须有明确拆除(否公平性不过)。

**产出**:`design/clues.md`(卡表)+ `design/matrix.md` + `design/chain.md`。

**完成门**:解题链闭合;矩阵无"真结局要素 = ✗"冲突;每张红鲱鱼有回收方案。

---

## Phase 3 · 游戏结构设计(1–2 天)

把矩阵变成可玩的拓扑。

**动作**
1. **章节曲线**:每章一个悬念钩子 + 一次喘息;峰值动效每章 ≤1 次(演出纪律,
   DDLC 式动态范围)。
2. **分支拓扑**:
   - **选择点类型化**:获取型(拿哪条线索)/ 信任型(好感,决定谁开口)/
     行动型(风险、追逐)/ 沉默型(不选也是选)。
   - **合流原则**:合流点用"两线最小公共已知集"写;两线已知差异不在合流段提,
     留给后续分岔回收。
   - **门禁(gate)**:关键揭示(如终章对峙)的前置 = 最低线索集;不足则走
     "未解"支线。**门禁是公平性的结构保证**——结局可达性靠它,不靠运气。
   - **引擎约束(v0)**:图必须 DAG(verify 会抓环)。调查 hub(反复盘问同一人)
     不能循环 → 用"逐项列点 + 离开"的线性化调查代替;确需循环,先提引擎需求。
3. **结局树**(三层,参考 g00 的 END_TRUTH / END_MISS / END_WAIT):
   - 真相结局:解题链全亮(判定 = 多 flag 全满足);
   - 擦肩结局:信息不足但全身而退;
   - 歧途结局:被红鲱鱼带偏(指错人/信错人)。
4. **交互节点布置**:每章 ≥1 个调查或推理节点(连线玩法已验证);终章必须有
   指认/对峙。交互密度是"游戏感"的来源,不能全是读文。

**产出**:`design/structure.md`(章节曲线 + 分支图草稿 + 结局判定条件)。

**完成门**:分支图纸上无"不可能状态"(需要的线索在通往它的路径上不可得);
每个结局的判定条件写成明确的线索集。

## Phase 4 · 剧本写作(主体工期)

用 DSL 写 `games/gNN/chapters/*.md`(语法见 ADR-003)。

**写作规则(为文字舞台优化)**
- **一拍一句**:句号即呼吸停顿,演出层按标点切呼吸单元;长复合句拆开。
- **正典词条会被自动强调**(人名/地名/事件词变色、可圈注):正文出现这些词时
  要意识到它在发光,别滥用。
- **@fact 打点**:每处线索获得必须有 @fact(它同时是释放矩阵的落库和
  canon-lint 的锚点)。
- **台词可截断**:关键被打断的话,断点设计在句尾(演出层做尾字坠落)。
- **信息纪律**:写每段前扫一眼矩阵当前列,不写 ✗ 的内容。角色可以说谎
  (说谎 ≠ 作者泄底),但叙述者(旁白)不许说谎——除非本作叙诡方案明确允许
  (P0 已定)。
- **戏中文档**:信件/日记/剪报全文单独放 `games/gNN/docs/*.md`,剧本里引用,
  演出时按纸材质渲染。

**完成门**:全章编译过、图校验过(`npm run verify` 的编译与图部分)。

---

## Phase 5 · 演出标注(与 P4 穿插进行)

两层,能自动的绝不手工。

**自动层(零标注)**
- canon 词典强调(词条自动色偏/可圈注);
- 说话者声线与分侧站位(voice_hz + 左右锚点,数据来自 Phase 1 素材台账);
- 呼吸节奏(标点驱动);换场印章(地点变更自动盖);时间轴带(@fact 命中
  时间轴事件自动点亮年代点)。

**手工层(剧本内备注,精确到台词 id)**
- 峰值动效:每章 ≤1 次(闪白/坠落/聚光灯级),位置标 @peak;
- 聚光灯沉默:哪个词独占全屏;
- 台词截断:哪句被切;
- 推理连线:哪些推断用连线演出(通常给"玩家自己连出来"的时刻);
- 环境大字/雨雪参数:场景级。

**演出预算 lint(规划中的工具)**:连续两拍高动效 → 报错;每章峰值超 1 → 报错。
v1 先人工核对,工具化后并入 verify。

**完成门**:每章演出清单成文并与剧本同 PR;演出类改动附截图或 MD5 证据
(AGENTS 要求)。

## Phase 6 · 校验与试玩

**机器门(已有)**
- `npm run verify`:编译 + 纪元 + 图 + 结局全可达;
- `npm test`:e2e 全分支回放。

**公平性审查(新增,当前人工,逐步工具化)**
1. **矩阵兑现比对**:导出剧本实际 @fact / 线索出现顺序,与释放矩阵逐格比对;
   "矩阵说 ✗、剧本已给" = 设计事故,必须改。
2. **结局条件可达性**:真结局判定的每条线索,在通往该结局的每条路径上可得
   (由 P3 门禁结构保证;不要依赖全路径枚举——指数爆炸,见附录 D)。
3. **红鲱鱼拆除检查**:揭晓幕里逐条核对。

**盲测(≥2 人,不提前给任何信息)**
- 破案率 30%–70% 为健康区间(全破 = 太简单,全不破 = 线索链断了);
- 必问一句:"揭晓时你觉得公平吗?"——"我本可以想到"是及格线,
  "我怎么可能想到"= 回 Phase 2。

**完成门**:verify/test 全绿 + 公平性三项过 + 盲测记录入 `design/playtest.md`。

## Phase 7 · 发布归档

- tag `gNN-vX.Y.Z`;结局分布统计落库(给下一作设计回流数据)。
- **canon 披露更新**:本作揭开的 secret 打上 disclosed_in / first_appearance,
  下一作 assumes 即自动解锁(共享宇宙的复利)。
- 复盘:哪些线索卡没人拿、哪些分支没人走、哪次峰值动效被忽略 → 写进
  `design/retro.md`。

## 附录 D · 已知引擎边界(v0)与绕法

| 边界 | 绕法 | 根治 |
|---|---|---|
| 图必须 DAG(无环) | 调查 hub 用"逐项列点+离开"线性化 | 引擎支持受控环(带访问次数上限) |
| 守卫只支持 flag 存在性 | 结局判定 = 多 flag 全满足(AND 链);OR/计数用分支展开 | enter 指令扩运算 |
| 路径枚举指数爆炸 | 结局可达性靠门禁结构保证,不全枚举 | 状态空间搜索(节点×flag集)替换 enumerateRoutes |

边界若阻碍设计,先在 ADR 记录并评估引擎升级——**不许为绕过边界降公平性要求**。
