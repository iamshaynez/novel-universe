# ADR-007 离线优先：本地运行、本地存档、账号只做同步

日期：2026-10-31　状态：已接受（2026-10-31 按推荐项批准；AGENTS §1–§2 与 ADR-001/002/006 已同步修订）

## 背景

现行实现是**服务端驱动**：`advance/choose` 在服务端执行并落库，客户端每推进一拍都要一次往返。
2026-10-31 的弱网调研证明，这条链路就是体验问题的根源：

- **每拍依赖网络**：请求丢失 → 当前拍重播；开卷时存档列表请求失败被当成「没有存档」→ 续档标记被删 →
  玩家点作品名新开局，从第一章开始。
- **游客在服务端建号**：`GET /api/auth/me` 为每个访客自动创建游客用户，进度绑 cookie；
  标题页「游客进度仅存本机」与事实不符。
- **离线壳不能玩**：Service Worker 只预缓存 `offline.html`，离线启动只能看到离线页。
- **IR 反复下载**：每次开局/读档都经 `/api/games/:id` 重新下载整份 IR（g01 约 118 KB，响应未设缓存头）。
- **节点 ID 不稳定**：编译器按章计数生成节点 ID（`${ch.id}-n${++ctr}`）。章内插删一行，
  存量存档的 `nodeId` 整体平移，读档会落到别的台词，甚至落空。
- **换版检测失效**：线上镜像无 `.git`，构建也未注入 `NU_SHA`，`/api/version` 恒为 `0.1.0|snapshot`；
  #96 起哨兵只认 `version|sha`，部署后已打开的页面不再自动换版。

有利条件：引擎只有 `engine/state.mjs`、`engine/graph.mjs` 两个零 I/O 纯模块，无 Node 依赖，可原样在浏览器运行；
页面没有外部字体或 CDN 依赖；音效全部代码合成。架构提案 v0 原本就把存档定义为「天然可回放」的确定性数据。

## 目标

1. **加载完成后完全本地可玩**：首次访问之后，断网或服务器不可用时，开卷、续档、推进、选项、转写、
   结局、图鉴、导读全部可用。
2. **本地优先存档**：所有玩家（含未注册）的进度先写本机，玩法路径上没有任何网络请求。
3. **账号只做同步**：注册/登录后在后台与远端双向同步；同步失败只改变同步状态，不影响游戏。
4. **多端最终一致，永不丢进度**：同一账号多设备并发游玩时，最坏结果是多出一个分叉存档，而不是互相覆盖。

非目标：服务端权威判定与防作弊（单人叙事）；同一存档多人实时协作；首次访问即离线。

## 决策

### D1 运行时拓扑：引擎下沉到浏览器

```
┌──────────────── 浏览器（首访后可完全离线） ────────────────┐
│ web/player 演出 ── web/runtime 本地运行时 ── engine 纯内核  │
│        │                   │                                │
│        │              web/store（IndexedDB）                │
│        └──── web/sync 后台同步（可失败、可重试、不阻塞）    │
└────────────────────────┬────────────────────────────────────┘
                         │ HTTPS：内容包 / 账号 / 同步（全部可选）
┌────────────────────────┴────────────────────────────────────┐
│ server：静态与内容分发 · 账号 · 同步信箱                    │
│   ├→ tools/compile（编译即加载）   └→ sqlite（账号与同步文档）│
└─────────────────────────────────────────────────────────────┘
```

- 依赖规则：`web → engine`（仅纯内核）；`server → engine / tools`；web 与 server 只经 HTTP 交互；
  engine 不依赖任何层。
- 服务端不再执行游戏推进；`/api/games/:id/saves`、`/api/saves/*` 进入兼容期后下线（实施计划 M3）。
- 新增 `engine/save.mjs`（纯）：存档文档构造、版本向量比较与合并裁决、稳定锚点与内容迁移、`seekStop`。
- 随机与时间属于边界输入：开局 seed（`crypto.getRandomValues`）、存档 id（`crypto.randomUUID()`）、
  时间戳都在 web 层生成后传入；引擎内继续禁用 `Math.random()`/`Date.now()`。

### D2 离线包：编译即加载 + 内容寻址 + 生成式 Service Worker

启动时照旧编译全部作品（无 dist），另算两个指纹：每部作品的 `irHash`（规范化 IR 的 sha256 前 12 位），
以及整体 `bundle`（预缓存清单内全部文件内容的哈希）。

| 路由 | 内容 | 缓存 |
|---|---|---|
| `/engine/*.mjs` | 引擎模块只读直出（白名单、防路径越界） | `no-cache` + ETag |
| `/content/catalog.json` | 作品目录：标题、章节、结局、`irHash`、IR 地址 | `no-cache` |
| `/content/<gameId>.<irHash>.json` | IR | `public, max-age=31536000, immutable` |
| `/sw.js` | `web/sw.js` 模板 + 启动期生成的预缓存清单（路径、sha256、bundle） | `no-cache` |

- 预缓存清单由 `index.html` 入口模块的 import 图自动导出，再加 manifest 与图标；
  **不含** `canon.html`（创作内部页）与分享卡。安装时逐个以 `fetch(url, { cache: 'no-cache', integrity })`
  校验哈希，保证不会混入 CDN 或浏览器的旧副本。
- 运行时策略：壳、引擎、内容缓存优先（按 `bundle` 分版本缓存）；`/api/*` 永不缓存；导航请求回 `index.html` 壳。
- 版本更新改由 Service Worker 生命周期驱动：去掉安装即 `skipWaiting()`；新版在后台装好后进入 waiting，
  页面在安全点（封面，或局内拍间停点）通知激活并重载，重载后从本地续读，零网络依赖。
- `/api/version` 改报 `{ bundle, protocol, boot, now }`（保留 `version/sha` 供旧页面过渡），
  只用于诊断与同步协议协商；30 秒轮询哨兵退役。

### D3 本地存储：IndexedDB

- 库 `novel-universe`：`saves`（主键 `id`；索引 `gameId`、`dirty`、`updatedAt`）、
  `collections`（每部作品的结局集与图鉴集）、`meta`（`deviceId`、`account`、`syncCursor`、`lastPlayed`、`legacyImported`）。
- 本地 schema 按版本号逐级升级，纪律同服务端迁移：只增不改、编号不复用、有测试。
- **先落盘再演出**：每次推进在一个 IDB 事务内写入新存档，写成功后才渲染下一拍；崩溃或刷新不丢拍。
- 多标签：Web Locks 保证同一存档同一时刻只在一个标签页推进（另一页等待锁）；同步只在持有 `nu-sync` 锁的标签页运行；
  存档列表在下一次开卷或同步时刷新。BroadcastChannel 跨标签即时通知列为后续增强。
- 尽力申请 `navigator.storage.persist()`，降低被浏览器清理的概率。

### D4 存档文档模型：快照为权威 + 版本向量

```js
SaveDoc = {
  schema: 1,
  id,                    // 客户端生成的 UUID：离线建档无需服务器
  gameId,
  run,                   // 引擎 run 快照：权威状态
  irHash,                // 计算该快照时的内容版本
  anchor,                // { nodeId, scene, ord, h }：场景标签 + 场景内序号 + 节点内容指纹
  vv,                    // 版本向量 { [deviceId]: n }
  summary,               // { chapter, chapterTitle, ended }：列表展示用派生字段
  createdAt, updatedAt,  // 客户端时钟：只用于展示，不参与裁决
  deleted,               // 可选：墓碑
  forkOf,                // 可选：分叉来源
}
```

- **只有玩法写入**（推进、选择、转写、分叉、删除）在本机分量上 `+1` 并标记 `dirty`；
  补全锚点、内容迁移等派生变更不递增，避免多设备各自迁移时产生假冲突。
- 结局与图鉴是**只增集合**，按（账号, 作品）取并集合并，永不冲突；与存档分开保存，删存档不丢收集。

### D5 内容版本迁移：稳定锚点

节点 ID 规则不改（不破坏 ADR-003 的 IR 合同），存档另记锚点。读档时若 `irHash` 与当前不同，按序解析：

1. 同 ID 且内容指纹相同 → 原位；
2. 同场景内指纹相同 → 原位（章内插删行导致的平移）；
3. 全作唯一指纹匹配 → 原位（场景改名）；
4. 场景开头（`ir.scenes[scene]` 之后的第一个停点）；
5. 本章开头；
6. 作品入口。

第 4 步起提示「剧本已更新，已回到『…』开头」；flags 原样保留。若存档来自更新的内容版本而本机尚未更新，
同样解析，但非原位命中时优先提示「联网更新后继续」。

### D6 同步协议 v1：推拉合一、可安全重放

`POST /api/sync`（需会话；`Content-Type: application/json`；请求头 `X-NU-Sync: 1`）：

```js
// 请求
{ protocol: 1, deviceId, cursor,                       // cursor：上次拉到的服务端序号
  push: [SaveDoc, ...],                                // 本机 dirty 存档（完整文档，≤50 份/次）
  collect: { [gameId]: { endings: [], cards: [] } } }
// 响应
{ cursor, more,                                        // more=true 时继续拉
  results: [{ id, status: 'accepted' | 'stale' | 'conflict', doc? }],
  pull: [SaveDoc, ...],                                // cursor 之后变化的文档（含本次刚接受的）
  collect: { [gameId]: { endings: [], cards: [] } } }  // 并集结果
```

服务端裁决（`P` = 推上来的版本向量，`S` = 服务端现存）：

| 关系 | 处理 |
|---|---|
| 无现存 | 插入，序号 +1，`accepted` |
| `P` 领先 `S` | 覆盖，序号 +1，`accepted` |
| 相等 | 幂等空操作，`accepted`（响应丢失后的重试走这里） |
| `P` 落后 `S` | `stale`，返回 `S` |
| 并发 | 规范化内容相同 → 向量逐分量取大，`accepted`；否则 `conflict`，返回 `S`。墓碑与活档并发时活档胜 |

客户端合并：远端领先或收到 `stale` → 采用远端；本机领先 → 保留待推；相等 → 清除 `dirty`；
并发且本机有改动 → **把本机版本分叉为新存档**（新 id，`forkOf` 指回原档），原 id 采用远端版本。

- 收集集合直接取并集。
- 触发：存档写入后防抖 3 秒；`online` 事件；页面转后台（`fetch keepalive` 冲刷）与回到前台；
  页面可见时每 60 秒；登录/注册成功。
- 失败退避 2s → 5s → 15s → 60s 封顶（复用 `web/resilience.mjs` 的永久/瞬时失败判定）；
  `401` → 暂停同步并提示重新登录；协议版本不符 → 提示更新。
- 上限：单文档 ≤64 KB、单次推送 ≤50 份、单用户 ≤500 份；单次拉取 ≤200 份并分页。
- 服务端只校验文档形状与大小，不重放剧情。

### D7 账号与身份

- **游客 = 纯本机**：没有任何服务端身份，可完整游玩、存档、收集。
- `GET /api/auth/me` 不再自动创建游客；无会话返回 `{ user: null }`。
- 注册/登录成功后立即同步：本机存档全部上推（成为账号存档），远端存档拉到本机（取并集）。
- 退出登录：先尽力同步；成功则清除本机该账号数据（默认，保护共享设备）；
  存在未同步内容时让玩家选择「保留为本机进度」或「放弃」。
- 会话过期只暂停同步，游戏不受影响。
- 遗留游客会话：兼容期内允许只读拉取一次完成导入，导入后客户端注销该会话；游客会话不得推送。

### D8 服务端数据模型（迁移 004-sync）

```sql
CREATE TABLE IF NOT EXISTS sync_docs (
  user_id    INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  doc_id     TEXT    NOT NULL,
  game_id    TEXT    NOT NULL,
  seq        INTEGER NOT NULL,          -- 用户内单调写入序号（拉取游标）
  vv_json    TEXT    NOT NULL,
  body_json  TEXT    NOT NULL,          -- SaveDoc，服务端只校验形状与大小
  deleted    INTEGER NOT NULL DEFAULT 0,
  updated_at TEXT    NOT NULL DEFAULT (datetime('now')),
  PRIMARY KEY (user_id, doc_id)
);
CREATE INDEX IF NOT EXISTS idx_sync_docs_seq ON sync_docs(user_id, seq);

CREATE TABLE IF NOT EXISTS sync_heads (
  user_id INTEGER PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,
  seq     INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE IF NOT EXISTS collections (
  user_id    INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  game_id    TEXT    NOT NULL,
  kind       TEXT    NOT NULL CHECK (kind IN ('ending', 'card')),
  key        TEXT    NOT NULL,
  first_seen TEXT    NOT NULL DEFAULT (datetime('now')),
  PRIMARY KEY (user_id, game_id, kind, key)
);
```

存量转换在同一迁移内完成（`INSERT OR IGNORE`，可重放）：有归属的 `saves` → `sync_docs`
（`doc_id = 'legacy-' || id`，向量 `{"legacy":1}`，`irHash` 为空表示「按当前 IR 解释」，锚点由客户端首次读档补全）；
`cards_seen` → `collections(kind='card')`；`endings_seen ⋈ saves` → `collections(kind='ending')`。
旧表在兼容期内保留，M3 再清理。

### D9 演出层随之调整

- **续读不是开篇**：读档/续档不重播章节卡与地点印章仪式；直接落氛围、HUD 章节与日期和当前拍，
  并以淡墨回显前两拍作上下文。
- 账籍栏显示同步状态：「本机进度 · 注册以多端同步」/「已同步 HH:MM」/「待同步 N 项」/「离线」/「需要重新登录」。
- 「离线就绪」提示：预缓存完成后告诉玩家可以断网游玩。
- 远端进度到达正在游玩的存档：在下一个停点自动跟进并提示；本机同时有新进度则分叉，
  提示「两台设备各自前进，已保留为两个存档」。
- 存档列表不再显示服务端整数编号，改为「第三章 · 河对岸 · 10-31 21:03 · 已同步/仅本机」。

## 考虑过的方案

| 方案 | 结论 | 理由 |
|---|---|---|
| 保持服务端驱动，加强重连 | 否 | 无法离线游玩；每拍仍受网络支配 |
| 动作日志作为同步真相（重放合并） | 否（v1） | 内容更新后选项/转写下标会变，跨 IR 版本重放会静默走错分支；快照 + 锚点更安全。可留作校验工具 |
| 按时间戳后写者胜 | 否 | 设备时钟不可信，且会静默覆盖另一端进度 |
| localStorage | 否 | 容量小、同步阻塞、无事务，难做多标签安全 |
| 引入 CRDT 库（Automerge/Yjs） | 否 | 违反零依赖；单人存档的冲突用版本向量 + 分叉已足够 |
| 依赖 Background Sync API | 否（可选增强） | 仅 Chromium 支持，iOS 不可用；以前台触发为主 |
| 静态 dist 发布（提案 v0 的 build.mjs） | 否 | 与 ADR-001「编译即加载」冲突；改为启动期内容寻址 |

## 后果

### 正面

- 玩法路径零网络：弱网、断网、部署窗口都不再影响推进；「跳回章首/第一章」一类问题从结构上消失。
- 服务器从「每拍必经」降为「可选的同步信箱」，负载与故障面大幅缩小。
- 内容更新有了明确的存档迁移语义（锚点），不再静默错位。
- 换版检测基于内容指纹，不依赖构建注入。

### 代价与风险

- **浏览器存储可能被清理或隔离**：iOS Safari 对未安装到主屏幕的网站有 7 天清理策略；
  Safari 标签页与主屏幕应用的存储互相隔离。未注册玩家的进度在这些情况下可能丢失或不互通。
  缓解：标题页对游客给出提示，鼓励安装或注册；导出/导入存档文件列为后续。
- 测试大面积重写：`api`（18 例）、`auth`（10 例）、`e2e`（8 例）围绕服务端推进，
  需改为引擎回放 + 同步接口 + 双客户端收敛测试。
- 兼容期内新旧接口并存；客户端新增存储、运行时、同步三块代码。
- IndexedDB、Service Worker、Web Locks 无法在 `node:test` 中直接运行：逻辑放在可注入适配器的纯模块里测试，
  浏览器端以离线演练截图作证据。

## 宪法与 ADR 修订（批准后执行）

- AGENTS §1：依赖方向改为 D1 规则；新增「离线优先」原则（首访后完全本地可玩，任何玩法路径不得依赖网络；
  服务端只做内容分发、账号与同步）；确定性一行改为「建档 seed 在客户端 web 层边界生成」。
- AGENTS §2：新增三条完成定义——本地 schema 升级须有测试；同步协议变更须升 `protocol` 并兼容上一版；
  离线完整性门（入口可达模块与内容必须全部在预缓存清单内，壳内不得引用外部资源）。
- ADR-001 更新依赖图；ADR-002 增补本地存储迁移纪律；ADR-006「持久化」段改为本地收集 + 同步。

## 测试策略（TDD 顺序）
