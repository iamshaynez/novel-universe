## 1. 服务器：部署目录与脚本

```sh
ssh <user>@gb-test
sudo mkdir -p /opt/apps/novel-universe && sudo chown -R $USER /opt/apps/novel-universe
# 本仓库 docker/ 三文件放进去：
#   docker/build-remote.sh    -> /opt/apps/novel-universe/build.sh    （受限命令：构建+推送+部署）
#   docker/deploy-remote.sh   -> /opt/apps/novel-universe/deploy.sh   （pull 幂等 + up + 冒烟）
#   docker/docker-compose.yml -> /opt/apps/novel-universe/docker-compose.yml
chmod +x /opt/apps/novel-universe/build.sh /opt/apps/novel-universe/deploy.sh
mkdir -p /opt/apps/novel-universe/data   # sqlite 落这里（容器内 /data/novel.db）

# compose 的 ${ACR_REGISTRY} 由同目录 .env 提供（docker compose 自动读取）：
echo 'ACR_REGISTRY=crpi-xxxx.cn-heyuan.personal.cr.aliyuncs.com' > /opt/apps/novel-universe/.env
chmod 600 /opt/apps/novel-universe/.env

docker login <ACR_REGISTRY>   # 服务器侧一次，供 build.sh 推送与 compose pull
```

## 2. 服务器：受限部署密钥（专用密钥对，绝不复用 app41 的）

```sh
# 本机生成专用密钥对（无口令）
ssh-keygen -t ed25519 -f ~/.ssh/novel-deploy -N '' -C 'novel-universe-deploy'

# 服务器 authorized_keys 追加（强制命令接管 build.sh + 关闭一切转发/终端）：
command="/opt/apps/novel-universe/build.sh",no-port-forwarding,no-X11-forwarding,no-agent-forwarding,no-pty ssh-ed25519 AAAA... novel-universe-deploy

# 私钥全文 -> 仓库 secret DEPLOY_KEY
```

CI 连接时以远程命令传 commit sha，build.sh 经 `$SSH_ORIGINAL_COMMAND` 读取并
校验（只认 40 位十六进制）——该密钥除「构建部署本仓库指定提交」外做不了任何事。

## 6. 接入层（chengdu.xiaowenz.com → 服务，已配置）

gb-test 入口是 1Panel 的 **openresty** 容器（占 80/443，无 tunnel，CF 直连源站）：

- **网络**：compose 底部 `networks.default.name=apps, external: true` 使容器加入
  openresty 所在的共享 `apps` 网络（nginx 以容器名 `novel-universe:3000` 反代）。
- **路由**：`/opt/openresty/conf.d/domains.conf` 追加 chengdu 两个 server 块
  （80 + 443，与 41/ask/card 等既有站点同构；改动前先带日期备份该文件）。
- **证书**：`le.crt` 是 acme.sh（`/root/.acme.sh`，cron 每日 4 次续期）管理的
  多域 SAN 证书，主域 money.xiaowenz.com——chengdu 已并入 SAN；重签命令见
  acme.sh conf（webroot `/opt/openresty/acme`，装到 `/opt/openresty/certs/le.*`，
  reloadcmd 自动 reload openresty）。
- **CF**：当前 Flexible（CF 终结 TLS、回源走 80）；源站 443 + 证书已备好，
  随时可切 Full(strict) 无需再动服务器。
