g01 存档膨胀与冲突回退修复（v0.5.4 候选）验收证据
日期：2026-11-02 · 分支 fix/save-bloat-and-fork-redirect

一、用户报告与根因

线上测试仍出现跳回；存档越刷越多——理论上一个用户的存档不应膨胀。

根因 1（线上残余跳回）：v0.5.1 把冲突热切改成了静默，但主线槽位仍按协议
被服务器副本顶替；正在玩的一局下一次 advance 从库里重读主线——读到的是
被顶替后的旧位置，位置悄悄回退（两个容器同账号时每轮同步都可复发）。
根因 2（存档膨胀）：封面卡片点击 = 无条件 startGame 新开一档。今天四次
部署造成的封面弹回，每次点卡片都多一档；没有任何回收机制。次要源：
每次并发冲突产生一个分叉档（合理但无标注、无活动局重定向）。

二、修复（TDD，先红后绿）

1. web/sync.mjs：冲突分叉后回调 onFork(fork)——分叉承载本机谱系与位置；
   主线槽位仍按协议接受远端（服务器端收敛不变）。
2. web/player.mjs onFork 接线：活动局（fork.forkOf === app.saveId）改走
   分叉谱系：app.saveId = fork.id + markLastPlay + toast 告知。此后每一拍
   advance 读写分叉，绝不读到被顶替的主线——位置回退根治。
3. 封面卡片：存在未完成档时点击 = 续读该档（loadSave），不再新开；
   「开新局」成为显式小按钮。存档膨胀从源头关闭。
4. 存档列表：forkOf 档标注「分支 · 」，多档时玩家可辨认谱系。

三、自动验证

- offline-first 新增：冲突分叉必须 onFork（分叉承载本机位置 n5、forkOf、
  dirty 待推、不触发 onRemote）。
- session-resilience 新增接线合同：卡片优先续读 / 显式开新局 / onFork
  重定向 app.saveId / 分支标注。
- 全量 npm test 268/268；npm run verify PASS（E1/E2/E3，2160 条路线）。

四、真实浏览器验证

本机 IndexedDB 预置 11 份未完成测试档：封面显示「开新局」按钮；点击
游戏卡片 → 直接续读（存档数 11→11，不再 +1），章节标签与入档提示正常。
