g01 存档删除（本机 + 远端同步清理）验收证据
日期：2026-11-02 · 分支 fix/save-delete

一、需求

存量存档（本地与远端）可删除——此前存档只增不减，无任何删除入口。

二、设计（沿用同步协议既有墓碑通道）

- 删除 = 墓碑：`LocalRuntime.remove(id)` 置 `deleted:1` + `dirty:1` +
  版本向量自增（bumpVV），幂等（已删再删不炸）。墓碑随 queueSync 推到
  服务器；其他设备拉取后活档被墓碑替换，列表随即清空——「远端删除」
  不需要新协议。服务器侧「墓碑与活档并发时活档胜」的规则不变。
- 存档面板每行新增「删」钮：armConfirm 二次确认（500ms 反射双击防护、
  2.5s 自动解除，确认态红框）；删除后原地刷新列表不关面板。
- 守卫：正在进行的当前局不能删（回到封面后再删），防自锯运行中的 runLoop。
- armConfirm 的 onclick 统一 stopPropagation——确认钮不得把点击冒泡给
  宿主行（此前点「删」会先触发该行的「读取存档」）。
- 收集（结局/图鉴）是只增合集，与存档删除解耦——删档不清收集。

三、自动验证（TDD，先红后绿）

- offline-first 新增 2 场景：删除即墓碑（本机列表消失/置脏/幂等）；
  墓碑经同步传播（A 删 → B 拉墓碑 → 两端列表清空且 B 侧保持墓碑态）。
- 全量 npm test 270/270；npm run verify PASS（E1/E2/E3，2160 条路线）。

四、真实浏览器验证

本机预置 11 份存档实测：点「删」→ 红框「确认？」→ 500ms 内连点被忽略 →
确认后存活档 11→10、墓碑 1、面板原地刷新；对当前局点删被守卫拦截
（提示回到封面后再删）。截图：g01-存档删除-面板与二次确认.png。

五、边界说明

- 服务器 sync_docs 保留墓碑记录（含负载字节）用于跨设备传播与防复活；
  列表/同步面已不可见。彻底物理清除如需（隐私诉求）另立需求。
- 匿名（未登录）删除仅本机生效；登录后墓碑自动上推。
